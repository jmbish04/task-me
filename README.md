# Astro/Cloudflare Static App Template

You want a tech stack that is easy to spin up, easy to deploy, and easy to manage.
You want it to be simple when it can be, yet powerful enough to adapt to new requirements and functionality.

This quickstart project allows you to easily create and deploy a new website or webapp to Cloudflare workers. With Cloudflare you can take your entire website to completion with only a single vendor for Domain Registration, DNS, SSL, and Hosting.

The site is fully static by default (SSG) and can be hosted on any static content hosting service, but by using the Cloudflare adapter you are able to both host your website as well as create dynamic serverless endpoints using Astro Endpoints and Actions.

Use the ShadCN library and theming system to easily generate components and customize your typography presets, colors, and other theme properties.

## Considerations:

### Why Astro?

I wanted to create a baseline technical stack that maximalizes simplicity and efficiency at its core. I chose the Astro
framework because it offers an optimal blend of performance, extensibility, and developer experience. At its core Astro
is a
zero-Javascript-by-default SSG generator that is perfect for content-focused sites that require little to no user
interactivity. The framework's component-based approach and 'Islands Architecture', as well as its first-class support
for React makes it easy to add interactivity on only the parts of the site that need it.

Additional features of Astro include:

- **File Based CMS:** Astro's Content Collections make it easy to manage content collections in MDX or JSON [(docs)](https://docs.astro.build/en/guides/content-collections/)
- **Build-time Image Optimization:** Astro Images allows images to be optimized at build time. [(docs)](https://docs.astro.build/en/guides/images/)
- **SEO:** Autogenerated `robots.txt` and `sitemap-index.xml`. [(docs)](https://docs.astro.build/en/guides/integrations-guide/sitemap/)
- **SSR:** Easily swap to SSR mode on any page or component to fetch data or do computations on the fly. [(docs)](https://docs.astro.build/en/guides/on-demand-rendering/#enabling-on-demand-rendering)
- **Endpoints/Actions:** Easily create robust serverless functions that run on the cloudflare server. [(docs)](https://docs.astro.build/en/guides/endpoints/)
- **No Vendor Lockin:** Astro's adapters make it easy to change hosting providers without having to change any of your source code. [(docs)](https://docs.astro.build/en/guides/on-demand-rendering/#server-adapters)

### Why CloudFlare?

Using multiple providers for things like Domain Registry, DNS, SSL, Hosting, Database, Captcha, Analytics can become a
hassle. The cognative load required increases with each new service, and if you're using multiple paid services the
costs can balloon very quickly. I chose Cloudflare because it offers all the services listed above in one place. Meaning
you only need a single login to take your website from idea to reality. Cloudflare also has a generous free hosting
plan, meaning you can host your entire website for only the cost of the domain registry.

Additional features of Cloudflare include:

- **Built-in CI/CD:** Follow the
  steps [here](https://developers.cloudflare.com/pages/framework-guides/deploy-an-astro-site/#deploy-via-the-cloudflare-dashboard)
  to deploy using a Github Repo and cloudflare will automatically deploy your app when new changes are pushed. (
  Alternatively you can use Wrangler to deploy your application locally)
- **D1 Databases:** Small sqlite databases that can be plugged into your workers. They have a limited size allowance but
  are great for things like a basic authorization server or CMS. [(docs)](https://developers.cloudflare.com/d1/)
- **Turnstile:** A lightweight CAPTCHA alternative for contact forms [(docs)](https://developers.cloudflare.com/turnstile/)

</details>

## 🚀 Project Structure

Inside of your Astro project, you'll see the following folders and files:

```text
├── public/ <- Public assets that will be served at the root
├── src/
│   ├── assets/ <- For any images you want Astro to optimize
│   ├── components/ <- Reusable .astro or .tsx (React) components
│   ├── layouts/ <- Core layouts for your website
│   ├── lib/
│   ├── pages/ <- Astro's file based routing root
│   ├── styles/ <- Contains global css with Tailwind config
│   ├── types/
│   └── consts.ts <- Defines metadata about the site
├── astro.config.mjs
├── README.md
├── package.json
└── tsconfig.json
```

Any static assets, like images, can be placed in the `public/` directory.

Most static assets and images can be placed in the assets directory and loaded using Astro's Image [(docs)](https://docs.astro.build/en/guides/images/) functionality to automatically optimize and serve images.

## Getting Started

First off, you'll need to clone this repository template into your own repo. You can use Github's built in template generator from this repository's github page, or clone the files using your method of choice.

Once you're set up in your repository, install the necessary dependencies using your dependency manager of choice npm/yarn/pnpm.

`npm install` or
`yarn install` or
`pnpm install`

Then run the vite dev server using

`npm run dev` (or yarn/pnpm equivalent)

And that's it! You're off and running. Update the files in the `src/pages` to update and add new routes to your application.

The application is preconfigured with a React adapter so you can create React or astro components in `src/components` and use them directly in your astro pages! 🎉 (make sure to check out the gotchas section for details about using React in astro)

## 🧞 Commands

All commands are run from the root of the project, from a terminal:

| Command                   | Action                                                        |
| :------------------------ | :------------------------------------------------------------ |
| `npm install`             | Installs dependencies                                         |
| `npm run dev`             | Starts local dev server at `localhost:4321`                   |
| `npm run build`           | Build your production site to `./dist/`                       |
| `npm run preview`         | Build and test your app as it will function on Cloudflare     |
| `npm run deploy`          | Deploy to your worker using Wrangler (if not using GIT CI/CD) |
| `npm run astro ...`       | Run CLI commands like `astro add`, `astro check`              |
| `npm run astro -- --help` | Get help using the Astro CLI                                  |
| `wrangler login`          | Log in to the wrangler CLI (for deployment)                   |
| `wrangler deploy`         | Deploy your application (make sure to build it first!)        |

## Deployment (Cloudflare)

To deploy to cloudflare, make sure that you have a Cloudflare account with access to Workers. If you're ready to go live, purchasing and managing your domain through Cloudflare will make the process of linking your domain's DNS to your worker extremely simple. (See below)

<details><summary>Linking your worker to your domain DNS</summary>

- If your domain is managed through Cloudflare, updating your DNS can be done through the Worker settings on your worker's dashboard. In the 'Domains & Routes' section, add a custom domain to the worker. Enter the domain for your website (optionally with a subdomain) and Cloudflare will automatically update your domain's DNS to point to the worker. That's it! You're all good to go!

- If your domain is managed elsewhere, all you need to do is get your Cloudflare worker's url from the 'Domains & Routes' section in the worker settings and add that to your provider's DNS settings.

</details>

<br/>
<b>There are three main methods to deploy your application to a cloudflare worker:</b>

> <b>Important!</b> Regardless of which one you choose, you should make sure to update the wrangler.jsonc file in the respository and update the 'name' field. This name will determine the name of your Cloudflare worker once it is deployed.

### Option 1: Deploy locally using wrangler

<details><summary>See Details</summary>
You can always deploy directly from your local machine using cloudflare's Wrangler CLI tool. This is great for the early stages of a project or when you want to quickly test development changes in the production environment.

First, log into your cloudflare account using the Wrangler CLI tool `npx wrangler login`

Next, make sure to build your application locally using `npm run build`

Finally, run `npx wrangler deploy` to deploy your application to your cloudflare worker.

You should now see your worker in your Cloudflare dashboard. If you select it, you can then view your live application by clicking the preview button on the Worker dashboard.

</details>

### Option 2: Deploy using Cloudflare's worker CI/CD

<details><summary>See Details</summary>
Cloudflare's worker CI/CD is a great way to automatically deploy your application whenever you push changes to your remote repository.

To get started navigate to the 'Workers & Pages' section of your Cloudflare dashboard and click the 'Create' button to create a new worker.

Choose the 'Import a repository' option, and link your github account to Cloudflare, giving it access to just the repository for your application.

In the application setup, give your app a name, and make sure that the build command is set to 'npm run build'.

Select 'Create and Deploy' and you're all good to go! You can now view your worker on your Cloudflare dashboard. Any time that you push changes to the main branch of your repository, Cloudflare will automatically rebuild and deploy your app.

You can view build logs for your CI/CD process in the 'Deployments' tab of your worker dashboard.

</details>

### Option 3: Deploy using a 3rd Party CI (Github Actions/Gitlab CI-CD)

<details><summary>See Details</summary>
You can always deploy your application using any third party CI/CD system. Many tools have preconfigured deployments for Cloudflare workers. I recommend researching the options avaiable to you for your given CI/CD system, or you can simply deploy your application manually from your CI using Wrangler!
</details>

### Option 4: Deploying to other providers

<details><summary>See Details</summary>
This project is preconfigured for deployment on Cloudflare workers, but you can deploy it anywhere by simply updating the adapter in your `astro.config.js` file. Astro has adapters for many popular hosting providers/frameworks (Netlify/Node/Vercel) <a target="_blank" href="https://docs.astro.build/en/guides/integrations-guide/cloudflare/">(docs)</a> If your project is completely SSG and has no SSR functionality, you can remove the adapter completely and host your build files from any static hosting provider!
</details>
